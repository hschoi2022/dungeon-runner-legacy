

# 던전 러너 레거시 (Dungeon Runner Legacy)

소프트웨어공학 9→10→11주차 실습용 레거시 프로젝트입니다.
이 저장소의 코드에는 **코드 스멜이 의도적으로 심어져 있습니다** — 여러분의 임무는
(10주차) 현재 동작을 테스트로 고정한 뒤, (테스트를 켠 채) 리팩토링하고,
(11주차) 그 과정을 git 커밋과 PR로 남기는 것입니다.

## 시작하기 (10주차 실습)
1. 우상단 초록색 **Use this template → Create a new repository** — 이름: `dungeon-runner-본인영문이름 또는 학번`
2. 본인 저장소를 clone 한다
3. 시작 확인 — 아래 '두 가지 경로' 중 하나로 Run All → 초록 2 + 무시 6이면 준비 완료
※ 이 저장소는 11주차(형상 관리)에서 그대로 이어서 사용됩니다. push하면 Actions 탭에서 자동 확인 결과를 볼 수 있음(본인 확인용, 제출X).

## 두 가지 경로 (아무거나 하나)

### 경로 A: Unity 에디터 (권장)
1. Unity Hub에서 이 폴더를 프로젝트로 추가하고 엽니다 — **Unity 2022.3 LTS** 기준
   - **Unity 6 사용자**: 열 때 "버전 업그레이드" 확인 창이 뜨면 승인하면 됩니다. 동일하게 동작합니다.
2. 메뉴 `Window > General > Test Runner` → `EditMode` 탭 → `Run All`
3. 초록 2개(제공 테스트), 회색 6개(TODO — Ignore 상태)가 보이면 준비 완료입니다.

### 경로 B: 명령줄 (.NET SDK 8)
```
dotnet test ci/Game.Core.Tests.csproj
```
Unity 없이 같은 소스·같은 테스트가 실행됩니다 — 자동 채점(GitHub Actions)이 쓰는 경로입니다.

## 폴더 지도
| 위치 | 내용 |
|---|---|
| `Assets/Scripts/Game.Core/` | 레거시 게임 로직 — **엔진을 참조하지 않는** 순수 C# (수정 대상) |
| `Assets/Scripts/Game.Core.Tests/` | NUnit 테스트 — 제공 2 + TODO 6 (실습 A에서 작성) |
| `Assets/Scripts/Game.Unity/DemoRunner.cs` | 데모: 빈 씬에 부착하면 보상 정산 UI가 뜹니다 |
| `ci/` | Unity 없이 빌드·테스트하는 .NET 프로젝트 (자동 확인) |

## 규칙
1. **테스트의 기대값은 현재 동작이다** — 코드가 이상해 보여도, 기대값을 "올바른 값"으로 고치지 않습니다. (그 판단은 리팩토링이 아니라 기능 변경입니다 — 9주차 2.2)
2. 리팩토링 중 테스트가 빨간불이 되면 **되돌리고 더 작은 단계로** 다시 합니다.
3. `Assets/Scripts/Game.Core/` 밖(테스트의 기대값, ci 설정)은 실습 지시 없이 수정하지 않습니다.

## 참고
Unity 2022 LTS는 2025년 5월로 공식 지원이 종료되었습니다. 업계 신규 프로젝트는 Unity 6로
이동 중이며, 이 실습이 2022 기반인 것은 수강생 프로젝트 환경과의 호환(하위→상위 열림) 때문입니다.
